# בוט פפידו — שאלות והזמנות בוואטסאפ (דמו)

בוט שעונה על שאלות ומקבל הזמנות מקצה לקצה: משלוח או איסוף, מנות עם גדלים ותוספות, פרטי לקוח, סיכום, אישור, וכרטיס הזמנה למטבח. זוכר לקוחות חוזרים ("כמו פעם שעברה?").

## הרצה (5 דקות)

```bash
copy .env.example .env      # Windows (cmd/PowerShell). Mac/Linux: cp .env.example .env
notepad .env                # להדביק מפתח אחרי GEMINI_API_KEY= (חינם: aistudio.google.com/apikey)
npm test                    # 23 בדיקות בלי מפתח — תמחור, סל, אישור הזמנה
npm start                   # http://localhost:3000
```
ב-Notepad לשמור עם "All files" כדי שהקובץ לא יישמר בטעות כ-`.env.txt`.

בדף: צ'אט בצד אחד, ובצד השני **"מטבח"** שבו מופיעות ההזמנות שאושרו. ככה מראים לבעלים: מזמינים בצ'אט, והכרטיס קופץ במטבח.
"שיחה חדשה" = אותו לקוח חוזר. "לקוח חדש" = מוחק את הזיכרון שלו.

## איך זה בנוי

```
הודעה (ווב / Twilio / Meta)
        │
   agent.js  ── מודל השפה מבין מה הלקוח רוצה ובוחר פעולה
        │
   tools.js  ── כל הפעולות: סל, כתובת, סיכום, אישור. כל החישובים כאן, לא במודל
        │
 menu.js + business.js  ── התפריט מטאביט + מאגר הידע
        │
   kitchen.js ── הזמנה מאושרת → מטבח (כרגע: קובץ + מסך הדמו)
```

שלוש הגנות שחשוב לדעת עליהן:
- **מחירים רק מהקוד.** המודל לא מחשב סכומים. הסכום הסופי מגיע מ-`show_summary`.
- **אין אישור בלי סיכום.** `confirm_order` נכשל אם הסל או הפרטים השתנו מאז שהסיכום הוצג.
- **מנה או תוספת שלא קיימת נדחית** עם רשימת האפשרויות האמיתיות.

## הזמנה בלחיצות (בלי AI)

כל לחיצה על כפתור או שורה ברשימה מטופלת בקוד (`src/flow.js`), בלי קריאה למודל: מהיר, חינמי ותמיד מדויק.
משלוח/איסוף → קטגוריה → מנה (עם מחירי אישית/L) → גודל → (רוטב חובה בפיצה בהרכבה) → תוספות ושינויים (לחיצה מוסיפה/מבטלת) → עוד מנה / לסיום → תשלום → סיכום → ✅ מאשר.
טקסט חופשי עובד בכל שלב והולך למודל, שרואה את אותו סל. רק שם וכתובת נכתבים חופשי.

## תפריט בתמונות וכפתורים

- **תפריט:** "מה יש?" → הבוט שולח 3 עמודי תפריט מסודרים (פיצות אדומות, לבנות + תוספות, ראשונות/פסטות/סלטים), בנפרד למשלוח ולאיסוף. התמונות ב-`public/menu/`, נבנות מהנתונים — אחרי שינוי בתפריט:
  `npm i -D playwright && npx playwright install chromium` (פעם אחת), ואז `npm run menu-images`. אותו תפריט כדף: `/menu/delivery`, `/menu/takeaway`.
- **כפתורים:** משלוח/איסוף, גודל עם מחיר, "זהו, לסיום", "✅ מאשר". עד 3 אפשרויות = כפתורים, 4-10 = רשימה. אפשר תמיד גם לכתוב חופשי.
  - Meta Cloud API: כפתורים ורשימות אמיתיים של וואטסאפ.
  - Twilio Sandbox: רשימה ממוספרת, והלקוח עונה "1"/"2" (כפתורים אמיתיים ב-Twilio דורשים Content Templates).
  - תמונות לוואטסאפ דורשות `PUBLIC_BASE_URL` ב-`.env` (הכתובת מ-ngrok).

## לוגים, ניטור וטלמטריה

כל מה שקורה נכתב לקבצים ב-`logs/` (JSON, קובץ ליום, נשמר 14 יום):

| קובץ | מה יש בו |
|---|---|
| `logs/app-<יום>.jsonl` | הכל: כל הודעה (`turn.start`/`turn.end`), כל קריאה למודל (`llm.call` עם זמן, טוקנים, כלים), כל כלי (`tool.call` עם קלט ותוצאה), לחיצות (`flow.tap`), הזמנות, העברות לצוות, בקשות HTTP, שליחה לוואטסאפ |
| `logs/errors-<יום>.jsonl` | רק אזהרות ושגיאות (429/503, נפילות, תשובות ריקות, לחיצות לא מוכרות) |
| `logs/tests/<זמן>.tap` + `.junit.xml` | כל ריצה של `npm test` |
| `logs/evals/<זמן>.json` | כל ריצה של `npm run evals`: כל שיחה, כל כלי, מה נכשל, זמנים וטוקנים |

**traceId:** לכל הודעה של לקוח יש מזהה, וכל האירועים שלה (קריאות מודל, כלים, שגיאות) נושאים אותו — אפשר לראות בדיוק מה קרה בהודעה אחת.

- **מסך ניטור:** `http://localhost:3000/monitor` — הודעות, הזמנות, קריאות למודל, טוקנים, זמני תגובה, שגיאות, ולחיצה על שיחה מציגה את כל מה שקרה בה.
- **מהטרמינל:** `npm run logs` (אחרונים) · `npm run logs -- chats` (כל השיחות) · `npm run logs -- errors` · `npm run logs -- trace <id>` · `npm run logs -- stats`
- **פרטיות:** מספרי טלפון מקוצרים בלוגים (`LOG_PII=masked`). תוכן ההודעות נשמר כדי שאפשר יהיה לתחקר — לא להעלות את `logs/` לגיט (כבר ב-`.gitignore`).
- מפתח Gemini נשלח בכותרת ולא בכתובת, כך שהוא לא מופיע בשום לוג.

## חיבור לוואטסאפ

**Twilio Sandbox (עכשיו, בלי אימות עסקי):**
1. מריצים את השרת וחושפים אותו לאינטרנט: `npx ngrok http 3000` (או `cloudflared tunnel --url http://localhost:3000`)
2. Twilio Console → Messaging → Try it out → WhatsApp sandbox → Sandbox settings
3. "When a message comes in": `https://<הכתובת-מ-ngrok>/webhook/twilio`, POST
4. מהטלפון: שולחים `join <קוד>` למספר של Twilio, ואחרי זה כותבים לבוט

**Meta Cloud API (אחרי אימות העסק):** למלא `META_*` ב-`.env`, ובאפליקציה ב-Meta להגדיר Webhook ל-`/webhook/meta` עם אותו verify token. הקוד מוכן ב-`src/channels/meta.js`.

## שמירה ומזהים

| מזהה | מה זה | דוגמה |
|---|---|---|
| מזהה לקוח | מספר הטלפון (מגיע עם כל הודעת וואטסאפ). בצ'אט הדמו: `web:<מספר>` — נפרד מלקוחות אמיתיים | `972501234567` |
| מזהה שיחה | מההודעה הראשונה עד שההזמנה נסגרת או שעתיים בלי הודעות | `c-261014-8b9af4` |
| מזהה הודעה | הודעת לקוח + התשובה. זה גם ה-traceId בלוגים | `136e740ec05e` |
| מספר הזמנה | רץ, ומקושר לשיחה שבה נוצר | `#1001` |

כל הודעה נכנסת ונשמרת מיד: מצב השיחה (שלב, סל, פרטים), תמליל, לקוח והזמנות — כך שאתחול שרת לא מוחק שיחה באמצע.
ב-`/monitor` → "שיחות": רשימה, תמליל מלא, ולחיצה על הודעה מראה כל מה שקרה מאחוריה.
API: `/api/conversations?customerId=…`, `/api/conversations/<מזהה שיחה>`.

איפה זה נשמר (`src/storage.js`, אותו ממשק לשניהם):
- **קבצים** (ברירת מחדל) — `data/runtime/`. מתאים למחשב ולשרת עם דיסק קבוע.
- **Upstash Redis** (חינמי) — כשמגדירים `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`. מתאים לשרתים חינמיים שהדיסק שלהם נמחק.

## העלאה לשרת (Render + Upstash, הכל חינם, אפשר מהטלפון)

1. **מסד נתונים:** console.upstash.com → Create Database (Redis, אזור Frankfurt) → בעמוד ה-DB, בחלק REST API: להעתיק `UPSTASH_REDIS_REST_URL` ו-`UPSTASH_REDIS_REST_TOKEN`.
2. **שרת:** render.com → כניסה עם GitHub → New → **Blueprint** → לבחור את ה-repo. Render קורא את `render.yaml` ומבקש 4 ערכים:
   `GEMINI_API_KEY`, `ADMIN_PASSWORD` (סיסמה שתבחרו), ושני הערכים מ-Upstash → Apply.
3. אחרי 2-3 דקות: `https://papido-bot-xxxx.onrender.com` — הצ'אט. `/monitor` — ניטור (שם משתמש כלשהו + הסיסמה).
4. כל `git push` מעדכן את השרת לבד.

שימו לב: השרת החינמי נרדם אחרי ~15 דקות בלי שימוש, וההודעה הראשונה אחרי זה לוקחת ~30-60 שניות. הנתונים לא נפגעים (הם ב-Upstash).
Twilio: Webhook = `https://<הכתובת>/webhook/twilio`. תמונות התפריט עובדות לבד (Render נותן את הכתובת הציבורית).

## פרטיות
הבוט שומר שם, כתובת והזמנה אחרונה לכל מספר טלפון, ותמליל של כל שיחה (נמחק אחרי `CONVERSATION_RETENTION_DAYS`, ברירת מחדל 90 יום). על שרת ציבורי חובה `ADMIN_PASSWORD`. לפני שימוש אמיתי: להוסיף משפט שקיפות בהודעה הראשונה, ודרך למחוק לקוח לפי בקשה (`forgetCustomer` כבר קיים ב-store).
